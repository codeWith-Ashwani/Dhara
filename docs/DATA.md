# Data register

## Current replay fixture

`data/replays/pune_ward14_48h.jsonl` is a synthetic 48-hour sequence based on the report's worked urban-flood scenario. It exercises all Sprint 1 adapters and includes a rainfall build-up, rising gauge, pump interruption, and rising external forecast probability.

It must not be used to claim predictive performance. Its only purpose is deterministic pipeline testing.

## Sprint 2 model-contract fixture

`data/training/synthetic_sensor_episodes.csv` contains ten deterministic synthetic episodes and 120 feature rows. It exists to exercise grouped evaluation, calibration, model persistence and inference contracts. The generated evaluation report always carries `operational_performance_claim: false`.

Rebuild it with:

```bash
python scripts/build_synthetic_sensor_fixture.py
```

## Sprint 3 adversarial replay

`docs/reports/sprint3_adversarial_results.json` is a deterministic software-safety artifact generated by `scripts/run_sprint3_adversarial_demo.py`. It compares a fifteen-report same-device attack with four independent, spatially spread reports. All identities, media references, classifications and locations are synthetic; the artifact validates policy behavior and makes no field-performance claim.

## Sprint 4 acceptance replay

`docs/reports/sprint4_acceptance_results.json` is generated by `scripts/run_sprint4_acceptance_demo.py`. It carries a synthetic corroborated Warning through the dossier, officer audit, multilingual template boundary, three sandbox channels, CAP v1.2 test composition and offline SMS codec. It contains no recipient data and proves only the deterministic software contract.

## Sprint 5 pilot rehearsal

`docs/reports/sprint5_rehearsal_results.json` is generated by
`scripts/run_sprint5_pilot_rehearsal.py`. It repeats the synthetic 48-hour replay 25 times,
creates eight synthetic confirmed/refuted outcomes, executes the idempotent learning job, and
records load, calibration-promotion, privacy, adapter-outage and shadow-mode checks. Random job
identifiers and measured timings make the generated artifact run-specific. It contains no real
citizen, recipient or authority data and sets `operational_performance_claim: false`.

Outcome rows and internal learning artifacts may contain actor, report and reporter references
and therefore belong in access-controlled operational storage. The public metrics projection
removes those fields and suppresses samples smaller than five. The threshold is a prototype
privacy floor, not a completed re-identification assessment.

## Ground truth needed for Sprint 2

For the chosen pilot wards, acquire at least five monsoon seasons where possible:

- timestamped IMD rainfall/radar snapshots;
- CWC/India-WRIS gauge and reservoir series;
- ULB drainage, pump and waterlogging logs;
- road closure, response and verified flood-onset records;
- static DEM, drainage-catchment and ward geometry;
- imagery labelled by flood/not-flood and ordinal depth.

Every source must have an owner, licence, acquisition date, spatial/temporal resolution, missingness profile and transformation history in a versioned manifest. News reports may help discover events but should not be treated as sole ground truth.
